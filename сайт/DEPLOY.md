# Выкладка сайта на сервер

Нужен Linux-сервер (VPS) с доменом. Ниже — вариант с systemd и Caddy (HTTPS получается сам).

## 1. Собрать компилятор и сайт

```
git clone https://github.com/nikitosklim/Sfera
cd Sfera && cargo build --release
cd сайт
../target/release/запустить сервер.код --только-собрать     # получится ./сервер
```

(Для сборки нужны Rust и LLVM 18 — как в README проекта. Либо соберите на своей машине
Linux и скопируйте на сервер папку `сайт/` вместе с бинарником `сервер`.)

## 2. Запуск сервисом (systemd)

Файл `/etc/systemd/system/sfera-site.service`:

```
[Unit]
Description=Сайт языка Сфера
After=network.target

[Service]
WorkingDirectory=/opt/sfera/сайт
ExecStart=/opt/sfera/сайт/сервер 8080
Restart=always
RestartSec=2
# Сервер течёт по ~1 КБ на запрос — раз в сутки перезапускаем для чистоты.
RuntimeMaxSec=86400
User=sfera

[Install]
WantedBy=multi-user.target
```

```
sudo useradd -r -m sfera
sudo chown -R sfera /opt/sfera/сайт
sudo systemctl enable --now sfera-site
```

Рабочая папка обязательно `сайт/` — все пути в программе относительные.

## 3. HTTPS и домен (Caddy)

`/etc/caddy/Caddyfile`:

```
sfera.example.ru {
    reverse_proxy localhost:8080
}
```

Вариант с nginx:

```
server {
    server_name sfera.example.ru;
    client_max_body_size 2g;          # загрузка установщиков через /admin
    proxy_request_buffering off;
    proxy_read_timeout 600s;
    location / { proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host; proxy_buffering off; }
}
```
(сертификат — через `certbot --nginx`). `proxy_buffering off` нужен, чтобы большие установщики
не копились в памяти nginx.

## 4. Токен для загрузки файлов

```
./make-token.sh          # Windows: .\make-token.ps1
```
Создаст `admin-token.txt` (в git не попадает). Откройте `https://ваш-домен/управление`, введите токен,
выберите файл — он попадёт на страницу «Загрузки» с SHA-256. Без `admin-token.txt` загрузка выключена.
Загружайте только по HTTPS (иначе токен виден в сети). Лимит — 2 ГБ, имя файла — латиницей.
Из командной строки: `curl -X PUT -H "Authorization: Bearer $(cat admin-token.txt)" -T файл.zip https://домен/загрузить/файл.zip`.
Файл с уже существующим именем не перезаписывается — добавляйте версию в имя.
Удалить файл: на странице `/управление` (раздел «Удалить файл») или `curl -X DELETE -H "Authorization: Bearer $(cat admin-token.txt)" https://домен/загрузить/файл.zip` — убирает файл с диска и строку из `list.txt`.

## 4а. API для программы-проводника

Сервер отдаёт для программы-проводника (список файлов, сведения о сервере, скачивание). Всё доступно только с тем же токеном, что и загрузка (`Authorization: Bearer …`):

- `GET /api/файлы?путь=папка` — содержимое папки в ЗОС: имя, папка или файл, размер, дата;
- `GET /api/сервер` — ОС, процессор, память, диск, время работы, нагрузка;
- `GET /api/скачать?путь=папка/файл` — файл с докачкой.
- `PUT /api/загрузить?путь=папка/файл` — принять файл (тело запроса); существующий не перезаписывается (409), лимит 2 ГБ.

Клиент для этих ручек — программа «Проводник» (`инструменты/проводник`, описание в документации «Программа Проводник»).

Корень проводника — папка `downloads`. Чтобы показывать другую папку, положите рядом с сервером файл `проводник-корень.txt` с одной строкой — путём к папке (например `/var/sfera/files`). Выйти за корень нельзя, скрытые файлы не показываются.

**Полный доступ ко всему серверу.** Напишите в этот файл просто `/` (`echo / > /opt/sfera/сайт/проводник-корень.txt`): проводник покажет весь диск, включая системные папки и скрытые файлы, с правами процесса сайта (под `root` — всё). Перезапуск не нужен, вернуть обычный режим — удалить файл. Токен администратора при этом равен доступу к компьютеру: только `https`, токен никому не показывать, при утечке пересоздать (удалить `admin-token.txt` и заново запустить `deploy-server.sh`). Большие папки отдаются страницами по 250 записей (параметр `стр`), формат `формат=2` — компактный список для программы.

## 5. Новые файлы и статьи

- Релиз целиком: скачайте артефакты из GitHub Actions в `~/Downloads` и выполните `./загрузить-релиз.sh` (сначала `--проверка`). Скрипт сам найдёт установщики и архивы, поставит имена с версией, названия и описания; `--заменить` перезаписывает уже загруженную версию. Токен: `SFERA_TOKEN` или файл `~/.sfera-token`.
- Установщик: `./add-download.sh файл "Название" "Описание"` — скопирует в `downloads/` и допишет
  строку со SHA-256 в `downloads/list.txt`. Перезапуск не нужен.
- Статья: положите `имя.md` в `content/articles/` и добавьте строку `имя | Название | Описание`
  в `content/articles/list.txt`. Документация, уроки и примеры — так же, в `content/docs/`, `content/lessons/`, `content/examples/`.
- Документация по темам получена из `ДОКУМЕНТАЦИЯ_ЯЗЫКА.md`; обновить: `python3 split-docs.py` (перезапишет файлы в `content/docs/`).
- Способы пожертвования: впишите ссылки в `support-links.txt`, сайт перезапускать не нужно.

## 6. Безопасность

- Запросы записываются в `access.log` (время, метод, адрес).
- Сервер принимает GET/HEAD и PUT на `/загрузить/` (только с токеном), пути проверяются на `..`, скачать можно только файлы из `list.txt`.
- Наружу открывайте только 80/443 (Caddy/nginx), порт 8080 держите закрытым файрволом.

## Быстрый путь: готовая сборка из GitHub Actions + `deploy-server.sh`

1. На GitHub: Actions → «Сайт для сервера» → Run workflow → скачать артефакт `sfera-site-linux` (zip с архивом `sfera-site-linux.tar.gz`).
2. Скопировать архив и скрипт на сервер (подставьте IP и пользователя):
   `scp sfera-site-linux.tar.gz сайт/deploy-server.sh root@IP:/root/`
3. На сервере: `sh deploy-server.sh sfera-site-linux.tar.gz 8080` — ставит сервис `sfera-site`, создаёт токен загрузки.
   Повторный запуск с новым архивом обновляет сайт, не трогая `downloads/` и токен.
4. Домен: в панели регистратора добавить A-запись на IP сервера, затем настроить nginx (пример выше) и `certbot --nginx -d ваш-домен`.
   Если на сервере уже работает другой сайт, это отдельный блок `server { server_name ...; }` на другом порту.

## Управление: статистика и статьи

Страница `/управление` (нужен токен из `admin-token.txt`) содержит три раздела:

- **Статистика**: просмотры, время на страницах и разделах, источники, поисковые запросы. Журналы лежат в `данные/` и сохраняются при обновлении сайта.
- **Статьи**: ссылки на статьи с Хабра и других сайтов. Вставьте адрес, сайт скачает страницу через `curl`, возьмёт название, описание и картинку, обложка сохранится в `данные/обложки/`. Теги пишутся вручную и участвуют в поиске.
- **Загрузки**: установщики для страницы «Загрузки».

Папку `данные/` стоит включить в резервные копии сервера.
