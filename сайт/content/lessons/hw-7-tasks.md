# Железо 7. Задачи: процессор на всех

До сих пор в нашей ОС работала одна программа. Научим ядро делить процессор между несколькими **задачами**: каждая думает, что процессор целиком её, а на самом деле таймер каждые 10 миллисекунд отбирает его и отдаёт следующей. Это называется вытесняющей многозадачностью.

## Что такое задача

Задача — обычная функция без параметров со своим стеком. Чтобы переключиться между задачами, достаточно **сохранить всё состояние процессора** (регистры, дробные регистры, место в коде) на стеке уходящей задачи и **загрузить** такое же состояние со стека новой. Всё сохранение уже делает стартовый код прерывания таймера (`examples/ос/запуск_ос.s`): он кладёт регистры на стек, зовёт нашу функцию на Сфере и переходит на тот стек, который она вернёт.

## Планировщик на Сфере

Наша функция получает адрес сохранённого кадра текущей задачи и возвращает кадр следующей:

```
функция sfera_irq_timer(целое кадр): целое
    аппаратная_запись32(0x300000, аппаратное_чтение32(0x300000) + беззнак32(1));
    порт_вывод8(0x20, беззнак8(0x20));
    вернуть задачи_переключить(кадр);
конец
```

А вот сам выбор следующей задачи, по кругу (библиотека `задачи_х86`):

```
функция задачи_переключить(целое кадр): целое
    целое текущая = читать64(0x300C08);
    писать64(0x300C10 + текущая * 24, кадр);
    целое число = читать64(0x300C00);
    целое следующая = текущая;
    целое проверено = 0;
    пока (проверено < число)
        следующая = следующая + 1;
        если (следующая >= число)
            следующая = 0;
        конец
        если (читать64(0x300C10 + следующая * 24 + 8) == 1)
            писать64(0x300C08, следующая);
            вернуть читать64(0x300C10 + следующая * 24);
        конец
        проверено = проверено + 1;
    конец
    вернуть кадр;
конец
```

В таблице по адресу `0x300C10` у каждой задачи три поля: сохранённый кадр, состояние (0 — место свободно, 1 — работает, 2 — завершена) и адрес кадра памяти со стеком. Основная программа — это задача 0.

## Новая задача

Новую задачу мы не запускаем, а **подделываем её прерванное состояние**: берём кадр памяти под стек и заполняем его так, будто задача уже работала и её прервал таймер. Остаётся написать, с какого места она продолжит:

```
писать64(кадр + 600, вход);     // rip: с какой функции начать
писать64(кадр + 608, 8);        // сегмент кода ядра
писать64(кадр + 616, 0x202);    // флаги: прерывания разрешены
писать64(кадр + 624, верх - 8); // вершина стека задачи
```

Когда планировщик вернёт такой кадр, прерывание «возвратится» прямо в начало функции задачи.

Адрес функции берём новым словом `адрес_функции`:

```
целое а = задача_создать(адрес_функции(задача_а));
```

## Две задачи на деле

Задачи в нашей демонстрации просто считают, пока их не остановят:

```
функция задача_а()
    пока (читать64(0x300F10) == 0)
        писать64(0x300F00, читать64(0x300F00) + 1);
    конец
    задача_завершить();
конец
```

Задача `б` такая же, но со своим счётчиком. Основная программа запускает обе, ждёт секунду, поднимает флаг остановки, ждёт завершения и проверяет, что обе работали. В ОС это команда `задачи`:

```
сфера> задачи
запущены задачи 1 и 2, основная ждёт секунду
задача 1 работала
задача 2 работала
задачи завершены, память возвращена
```

Все три потока, основной и две задачи, идут «одновременно», хотя процессор один: просто переключаются они сто раз в секунду.

## Что мы упростили

- задачи работают в режиме ядра и могут трогать любую память: настоящая защита (кольца процессора, свои таблицы страниц) впереди;
- общие данные задачи делят без блокировок, поэтому каждая пишет только в свои ячейки;
- стек задачи — один кадр памяти (4 КБ): глубокая рекурсия в задачах недопустима;
- задач не больше восьми, переключение строго по кругу.

Проверка: `examples/ос/проверить.sh` набирает команду `задачи` на клавиатуре и сверяет вывод.
