# Железо 4. Память: кадры и страницы

У процессора есть **виртуальная** память: программа видит адреса, а таблицы страниц решают, какому куску настоящей памяти (физическому **кадру** в 4 КБ) каждый адрес соответствует. Сделаем в нашей ОС два слоя: учёт кадров и таблицы страниц.

## Кадры

Выбираем простейшее устройство: битовая карта. Один бит — один кадр, 0 — свободен, 1 — занят. Библиотека `память_х86` узнаёт объём памяти у загрузчика и ведёт карту по адресу `0x500000`. Занятыми помечены ядро и всё, что до 6 МБ.

- `выделить_кадр()` находит первый свободный кадр и возвращает его физический адрес (или 0, если памяти нет);
- `освободить_кадр(адрес)` возвращает кадр обратно.

## Страницы

Адрес разбивается на части по 9 бит: четыре уровня таблиц, и последняя запись говорит, где лежит кадр. Функция `отобразить` проходит эти уровни, при необходимости создаёт таблицы и записывает запись нижнего уровня:

```
функция отобразить(целое виртуальный, целое физический, целое флаги)
    если (виртуальный < 0x40000000)
        паника("нельзя менять отображение первого гигабайта");
    конец
    целое п4 = наложить_маску(регистр_cr3(), 0x000FFFFFFFFFF000);
    целое п3 = таблица_ниже(п4, наложить_маску(сдвинуть_вправо(виртуальный, 39), 511));
    целое п2 = таблица_ниже(п3, наложить_маску(сдвинуть_вправо(виртуальный, 30), 511));
    целое п1 = таблица_ниже(п2, наложить_маску(сдвинуть_вправо(виртуальный, 21), 511));
    писать64(п1 + наложить_маску(сдвинуть_вправо(виртуальный, 12), 511) * 8, включить_биты(физический, флаги));
    сбросить_страницу(виртуальный);
конец
```

Первый гигабайт оставлен под ядро и устройства, поэтому отображение там менять нельзя: функция остановит ОС паникой.

## Подкачка по требованию

Самое интересное: мы не создаём страницы заранее. Область `0x40000000…0x4FFFFFFF` пуста. Когда программа обращается туда в первый раз, процессор вызывает **ошибку страницы**, и наш обработчик выделяет кадр, обнуляет его и отображает:

```
функция sfera_pf(целое код_ошибки, целое адрес)
    если (адрес >= 0x40000000 и адрес < 0x50000000 и наложить_маску(код_ошибки, 1) == 0)
        целое кадр = выделить_кадр();
        если (кадр == 0)
            паника("нет свободной памяти");
        конец
        кадр_обнулить(кадр);
        отобразить(наложить_маску(адрес, 0x7FFFFFFFFFFFF000), кадр, 3);
        память_задать(24, память_состояние(24) + 1);
        вернуть;
    конец
    // …иначе паника: выводим адрес и останавливаем процессор
конец
```

Программа ничего не замечает: команда записи просто повторяется и теперь удаётся. Проверим в нашей ОС командой `страницы`:

```
сфера> страницы
пишем число 42 по виртуальному адресу 0x40000000, страницы там пока нет
и 7 по адресу 0x40001000
читаем обратно:
42
7
обработано ошибок страниц: 2
взято кадров (две страницы и таблицы): 4
страницы возвращены
```

Две страницы, а взято четыре кадра: ещё два ушли на служебные таблицы. После `снять_отображение` и `освободить_кадр` команда `память` показывает, что свободных кадров осталось почти столько же.

Команда `сбой` обращается к запрещённому адресу, и ядро выводит «ПАНИКА: ошибка страницы по адресу …» вместо того, чтобы молча перезагрузиться.

Дальше: загрузим ядро без QEMU, нашим собственным загрузчиком.
