## Первая программа

```
функция главная() -> целое {
    вывести("Привет, мир!");
    вернуть 0;
}
```

Каждая программа обязана иметь функцию `главная`, возвращающую `целое`
(код завершения — `0` означает успех). Компилируется командой:

```bash
запустить привет.код -c
```

⚠️ **Без `-c` программа не только соберётся, но и сразу запустится** —
удобно для быстрой проверки. Флаг `-c` можно писать и кириллицей, как
`-с` (по первой букве слова "собрать") — оба варианта равнозначны и
работают одинаково. Внешне кириллическая "с" и латинская "c" выглядят
неотличимо на экране, но для компьютера это разные символы — поэтому
поддержаны **оба**, а не только один, чтобы привычная латинская `-c`
(как почти везде в мире разработки) продолжала работать без сюрпризов.
То же самое верно для `-b`/`-б` (`--библиотека`).

## Основы синтаксиса

- **Комментарии**: `//` до конца строки, `/* ... */` — многострочные
- **Каждый оператор заканчивается точкой с запятой** (`;`)
- **Блоки кода** — в фигурных скобках `{ }`
- Язык **полностью кириллический** — все ключевые слова, имена
  встроенных функций и типов пишутся кириллицей

## Типы данных

### Целые числа

| Тип | Размер | Знаковый |
|---|---|---|
| `целое` | 64 бита | да |
| `целое8` | 8 бит | да |
| `целое16` | 16 бит | да |
| `целое32` | 32 бита | да |
| `целое64` | 64 бита | да (то же, что `целое`) |
| `беззнак8` | 8 бит | нет |
| `беззнак16` | 16 бит | нет |
| `беззнак32` | 32 бита | нет |
| `беззнак64` | 64 бита | нет |

⚠️ **Важно**: типы разной разрядности **не смешиваются неявно** —
`целое32` и `целое` в одном выражении требуют явного приведения:

```
целое32 а = 5;
целое б = 10;
целое итог = целое(а) + б;   // явное приведение обязательно
```

### Дробные числа

`дробное` (по умолчанию, 64 бита), `дробное32`, `дробное64`.

### Текст

`текст` — строка. Литералы в двойных кавычках: `"привет"`.
Конкатенация — оператором `+`:

```
текст имя = "Аня";
текст приветствие = "Привет, " + имя + "!";
```

Экранированные последовательности внутри строк: `\n` (новая строка),
`\r` (возврат каретки — важно для сетевых протоколов вроде HTTP, где
строки заголовков разделяются именно парой `\r\n`), `\t` (табуляция),
`\"` (кавычка), `\\` (обратный слеш).

### Логический тип

`верно` — булев тип. Литералы: `да` (истина) и `нет` (ложь) —
**не** `true`/`false`.

```
верно готово = да;
если (готово) {
    вывести("Готово!");
}
```

## Переменные

Объявление — `тип имя = значение;`:

```
целое возраст = 25;
текст имя = "Иван";
верно активен = да;
```

### Неизменяемые переменные

Ключевое слово `неизменно` перед типом запрещает переприсваивание:

```
неизменно целое максимум = 100;
```

### Явные приведения типов

Синтаксис — имя типа как функция: `целое32(значение)`, `дробное(значение)`.

⚠️ **Важно**: приведение нужно даже при инициализации **числовым
литералом** — типы разной разрядности не смешиваются неявно нигде:

```
целое32 а = целое32(5);    // так, не "целое32 а = 5;"
целое итог = целое(а) + б;  // и здесь тоже явно
```

## Операторы

### Арифметические

`+` `-` `*` `/` `%` (остаток от деления)

### Сравнение

`==` `!=` `<` `>` `<=` `>=`

### Логические

`&&` (И) `||` (ИЛИ) `!` (НЕ)

### Побитовые

`&` (побитовое И) `|` (побитовое ИЛИ) `^` (побитовое исключающее ИЛИ) `~`
(побитовое отрицание, унарный) — только для целых чисел, оба операнда
должны быть одного типа:

```
целое а = 12;
целое б = 10;
целое и_результат = а & б;    // 8
целое или_результат = а | б;  // 14
целое искл_результат = а ^ б; // 6
целое не_результат = ~5;      // -6
```

⚠️ **Приоритет ниже, чем у сравнения** (та же схема, что в C/Rust,
намеренно, не случайно) — `а & б == 8` разберётся как `а & (б == 8)`,
не как `(а & б) == 8`. При смешивании с сравнением используй явные
скобки.

⚠️ **Сдвигов (`<<`, `>>`) в этой версии честно нет** — язык уже
использует `<`/`>` для обобщённых типов (`Список<целое>`), и вложенные
обобщённые типы (`Список<Список<целое>>`) дали бы лексеру два подряд
идущих `<`, которые легко перепутать с одним токеном сдвига — та же
ловушка, что была в ранних версиях C++.

### Текст

`+` — конкатенация. `==`/`!=` — сравнение по содержимому (не по адресу).

## Управляющие конструкции

### Условие

```
если (х > 10) {
    вывести("Больше десяти");
} иначе если (х > 0) {
    вывести("Положительное");
} иначе {
    вывести("Ноль или отрицательное");
}
```

### Цикл с условием

```
целое счётчик = 0;
пока (счётчик < 5) {
    вывести(целое_в_текст(счётчик));
    счётчик = счётчик + 1;
}
```

### Цикл по коллекции

```
целое[3] числа = [1, 2, 3];
для каждого элемент в числа {
    вывести(целое_в_текст(элемент));
}
```

⚠️ `для каждого` работает **только с массивом** — не со `Список<Т>` (для
перебора элементов списка используй обычный `пока` со счётчиком и
`.получить(индекс)`/`.размер()`).

## Функции

```
функция сложить(целое а, целое б) -> целое {
    вернуть а + б;
}
```

- Тип возврата указывается через `->` после списка параметров
- `вернуть` — оператор возврата значения
- Функция без возвращаемого значения просто не пишет `-> тип`:

```
функция напечатать_дважды(текст сообщение) -> целое {
    вывести(сообщение);
    вывести(сообщение);
    вернуть 0;
}
```

### Проверка аргументов при вызове

Компилятор проверяет и количество, и типы аргументов при каждом вызове
— как обычной функции, так и функции из подключённого модуля:

```
функция сложить(целое а, целое б) -> целое { вернуть а + б; }

сложить(5);        // ошибка: функция 'сложить' ожидает 2 аргумент(ов), передано 1
сложить(5, "три"); // ошибка: несовпадение типов для аргумента 2
сложить(5, 3);     // верно
```

Параметр, объявленный как контракт, принимает любую структуру, реально
его реализующую (`структура X : ИмяКонтракта`) — не только буквально
значение самого контракта.

### Обобщённые функции

Пока **не поддержаны** кодогенератором (обобщёнными могут быть только
структуры — см. раздел про обобщённые типы).

---

## Массивы

Фиксированного размера, размер — часть типа. **Требуют явной
инициализации** литералом при объявлении:

```
целое[5] числа = [10, 20, 30, 40, 50];
числа[0] = 99;              // обращение и запись по индексу
вывести(целое_в_текст(числа[0]));
```

## Структуры

```
структура Точка {
    целое х;
    целое у;

    функция сумма_координат() -> целое {
        вернуть это.х + это.у;
    }
}
```

- Поля объявляются как обычные переменные, без значений по умолчанию
- Методы — обычные функции внутри тела структуры
- **`это`** — ссылка на текущий экземпляр внутри метода (аналог
  `self`/`this` в других языках)
- **Конструктор генерируется автоматически**, по всем полям в порядке
  объявления:

```
Точка точка = Точка(3, 4);
вывести(точка.сумма_координат());   // выведет 7
```

Структуры — всегда объекты в куче (передаются по ссылке), с
автоматическим подсчётом ссылок — см. [ARC](#управление-памятью-arc).

### Слабые ссылки

Поле, объявленное как `слабая Тип`, не увеличивает счётчик ссылок —
нужно для разрыва циклических ссылок (например, родитель ↔ потомок):

```
структура Цель {
    текст имя;
}

структура Держатель {
    текст имя;
    слабая Цель цель;    // не увеличивает счётчик ссылок "Цель"
}

функция главная() -> целое {
    Цель цель = Цель("моя цель");
    Держатель держатель = Держатель("держатель", цель);
    вывести(держатель.цель.имя);
    вернуть 0;
}
```

### Проверка живости — `.жива()`

Перед обращением к цели через слабую ссылку можно (и нужно) проверить,
не была ли она уже освобождена — метод `жива()` доступен на любом
доступе к полю, объявленному как `слабая`:

```
если (держатель.цель.жива()) {
    вывести(держатель.цель.имя);
} иначе {
    вывести("цель уже освобождена");
}
```

Работает безопасно даже после того, как цель "логически" умерла (её
счётчик сильных ссылок дошёл до нуля) — пока жива хотя бы одна слабая
ссылка на неё, компилятор откладывает реальное освобождение памяти
именно для того, чтобы `жива()` могла её безопасно проверить, не
рискуя обращением к уже переиспользованной памяти. Как только
последняя слабая ссылка тоже перестаёт существовать — отложенное
освобождение происходит немедленно.

## Обработка ошибок — результат\<Т\>

Вместо исключений — обёртка `результат<Т>`, содержащая три поля:
`.успешно` (`верно`), `.значение` (тип `Т`, валиден только при успехе),
`.сообщение` (текст ошибки, валиден только при неудаче).

```
функция разделить(целое а, целое б) -> результат<целое> {
    если (б == 0) {
        вернуть ошибка("деление на ноль");
    }
    вернуть успех(а / б);
}

функция главная() -> целое {
    результат<целое> итог = разделить(10, 2);
    если (итог.успешно) {
        вывести(целое_в_текст(итог.значение));
    } иначе {
        вывести("Ошибка: " + итог.сообщение);
    }
    вернуть 0;
}
```

Многие встроенные функции (`подстрока`, `найти`, `прочитать_файл` и
другие) сами возвращают `результат<Т>` — обязательно проверяй
`.успешно` перед использованием `.значение`.

## Обобщённые типы

### Список\<T\>

```
Список<целое> числа = Список<целое>();
числа.добавить(10);
числа.добавить(20);

целое первое = числа.получить(0);
целое количество = числа.размер();
```

### Словарь\<Ключ, Значение\>

```
Словарь<текст, целое> возрасты = Словарь<текст, целое>();
возрасты.положить("Аня", 25);

результат<целое> возраст = возрасты.получить("Аня");   // ключ может отсутствовать!
если (возраст.успешно) {
    вывести(целое_в_текст(возраст.значение));
}

целое количество = возрасты.размер();
```

⚠️ В отличие от `Список.получить(индекс)` (возвращает значение
напрямую), `Словарь.получить(ключ)` возвращает `результат<Значение>` —
ключа может не быть в словаре, обязательно проверяй `.успешно`.

⚠️ **Важное синтаксическое ограничение**: `Список<Т>`/`Словарь<Ключ,
Значение>` нельзя объявить через вывод типа (простое присваивание без
явного типа слева) — всегда указывай тип явно, как в примерах выше.

### Обобщённые структуры (пользовательские)

```
структура Коробка<Т> {
    Т содержимое;
}

коробка = Коробка<целое>(42);   // без явного типа слева — только так!
вывести(целое_в_текст(коробка.содержимое));
```

⚠️ **Важное, честное ограничение**: пользовательскую обобщённую
структуру можно объявить **только через вывод типа** (без явного
типа в левой части) — `Коробка<целое> коробка = ...;` **не работает**
(семантика пока не умеет сопоставлять явно указанный обобщённый тип с
результатом конструктора). Это отличается от `Список`/`Словарь`,
которые можно объявлять и явно.

### Обобщённые функции

```
функция макс_из_двух<Т>(Т а, Т б) -> Т {
    если (а > б) {
        вернуть а;
    }
    вернуть б;
}

функция главная() -> целое {
    целое итог_целое = макс_из_двух<целое>(3, 7);        // 7
    дробное итог_дробное = макс_из_двух<дробное>(2.5, 1.5); // 2.5
    вернуть 0;
}
```

⚠️ **Честные ограничения этой версии**:
- Только **один** обобщённый параметр (как и у обобщённых структур)
- Тип нужно указывать **явно** при вызове (`имя<тип>(...)`) — вывод
  типа из аргументов без явного указания не реализован
- Только функции **главного файла** — обобщённые функции из
  подключённых модулей пока не поддержаны

## Контракты и полиморфизм

Контракт — описание требуемых методов, аналог интерфейса:

```
контракт Печатаемый {
    функция напечатать() -> текст;
}

структура Кот : Печатаемый {
    функция напечатать() -> текст {
        вернуть "Мяу";
    }
}

структура Собака : Печатаемый {
    функция напечатать() -> текст {
        вернуть "Гав";
    }
}
```

Компилятор на этапе сборки проверяет, что структура, заявляющая `:
Контракт`, реально имеет все требуемые методы с совпадающими
сигнатурами.

### Настоящий полиморфизм

Контракт можно использовать как тип параметра функции или переменной —
один и тот же код тогда работает с *любой* структурой, реализующей
контракт (динамический выбор нужной реализации в момент выполнения):

```
функция озвучить(Печатаемый существо) -> целое {
    вывести(существо.напечатать());
    вернуть 0;
}

функция главная() -> целое {
    Кот кот = Кот();
    Собака пёс = Собака();

    озвучить(кот);   // выведет "Мяу"
    озвучить(пёс);   // выведет "Гав" — та же функция, другая реализация

    вернуть 0;
}
```

⚠️ **Важно**: аргумент-структуру нужно сначала сохранить в переменную —
`озвучить(Кот())` (временный экземпляр напрямую, без промежуточной
переменной) **не работает**.

### Список\<Контракт\>

Коллекция разнотипных объектов через общий интерфейс — та же идея, что
выше, но много объектов сразу:

```
Список<Печатаемый> зоопарк = Список<Печатаемый>();
зоопарк.добавить(кот);
зоопарк.добавить(пёс);

целое индекс = 0;
пока (индекс < зоопарк.размер()) {
    Печатаемый существо = зоопарк.получить(индекс);
    вывести(существо.напечатать());   // "Мяу", затем "Гав"
    индекс = индекс + 1;
}
```

⚠️ **Известная утечка памяти в этой версии** (не крах, только утечка):
структуры, добавленные в `Список<Контракт>`, не "захватываются"
(увеличение счётчика ссылок ARC) — если единственная переменная,
хранящая структуру напрямую (`Кот кот = Кот();`), выходит из области
видимости раньше списка, список продолжает на неё ссылаться дольше, чем
следовало бы. На практике безопаснее держать исходные переменные
(`кот`, `пёс`) живыми столько же, сколько и сам список.

### Контракт как тип возврата функции

Функция может быть объявлена возвращающей контракт — вызывающий код
получает объект, не зная заранее, какая именно структура за ним стоит:

```
функция создать_питомца() -> Печатаемый {
    Кот кот = Кот();
    вернуть кот;
}

функция главная() -> целое {
    Печатаемый питомец = создать_питомца();
    вывести(питомец.напечатать());   // "Мяу"
    вернуть 0;
}
```

⚠️ Та же самая, уже известная утечка памяти, что и у `Список<Контракт>`
выше (тот же корень — ARC не "видит насквозь" структуру, упакованную в
контракт) — не крах, только утечка.

## Многопоточность

### параллельно

Запускает блок кода в отдельном потоке операционной системы:

```
параллельно {
    вывести("Работаю в фоне");
}
```

⚠️ **Важное ограничение**: тело блока `параллельно` **не может
использовать переменные из окружающей области видимости** (защита от
обращения к уже освобождённой памяти) — единственное исключение,
описанное ниже.

### дождаться_все_потоки()

Ждёт завершения **всех** потоков, запущенных через `параллельно` с
начала программы (или с прошлого вызова этой же функции):

```
параллельно {
    вывести("Поток 1");
}
параллельно {
    вывести("Поток 2");
}

дождаться_все_потоки();   // гарантированно оба потока уже завершились
вывести("Оба потока точно закончили работу");
```

⚠️ **Честное ограничение v1**: ждёт **все** потоки разом, нет способа
дождаться какого-то одного конкретного (потребовало бы более крупного
изменения — превращения `параллельно` из оператора в выражение,
возвращающее дескриптор потока). Максимум 256 потоков, запущенных без
вызова `дождаться_все_потоки()` между ними.

### канал\<T\>

Безопасный способ передать одно значение из фонового потока обратно:

```
функция главная() -> целое {
    канал<целое> канал_результата = создать_канал();

    параллельно {
        целое вычислено = 2 + 2;
        канал_результата.отправить(вычислено);
    }

    целое значение = канал_результата.получить();   // ждёт, пока не придёт значение
    вывести(целое_в_текст(значение));

    вернуть 0;
}
```

Поддерживаются только целочисленные и указательные типы значения (не
дробные, не встроенные напрямую структуры).

## Управление памятью (ARC)

Структуры управляются автоматически через подсчёт ссылок (ARC) —
писать `free`/`delete` не нужно, память освобождается сама, когда на
объект больше никто не ссылается.

Текст **частично** под управлением ARC — простые локальные переменные,
цепочки конкатенации, результаты некоторых функций и **текстовые поля
структур** отслеживаются и освобождаются автоматически.

⚠️ **Как именно устроено для полей структур**: каждое текстовое поле,
при записи (в конструкторе или прямым присваиванием `объект.поле =
...;`), автоматически получает **свою собственную копию** переданного
текста — независимо от того, был это литерал (`"Аня"`) или уже готовое,
вычисленное значение. Это гарантирует, что структура всегда владеет
содержимым своего текстового поля и может безопасно освободить его при
уничтожении — за счёт одного лишнего копирования памяти при каждой
записи такого поля.

Переприсваивание внутри циклов тоже корректно отслеживается — решение
"освобождать ли старое значение" принимается в рантайме через скрытый
флаг владения, а не один раз при компиляции (см. подробности в
`ИСТОРИЯ_РАЗРАБОТКИ.md`). Полный, честный список того, что ещё не
покрыто — в разделе "Известные ограничения" выше.

## Модули

```
подключить утилиты;
```

Подключает файл `утилиты.код` из той же папки (или из папки `пакеты/`,
если рядом файла нет — так подключаются установленные пакеты).

Доступ к содержимому — либо напрямую по имени, либо явно, через имя
модуля:

```
целое итог = удвоить(21);              // обычный вызов
целое итог2 = утилиты.удвоить(21);     // то же самое, но с указанием модуля
```

внешняя функция получить_переменную_окружения(текст имя) -> текст как "getenv";

## Компиляция под другую архитектуру процессора

По умолчанию компилятор собирает программу под ту же архитектуру, на
которой сам запущен. Флаг `--целевая-платформа` позволяет указать
любую другую — компилятор построен поверх LLVM, который уже умеет
генерировать код для множества архитектур, не только для той, что "под
рукой":

```bash
запустить программа.код -c --целевая-платформа aarch64-linux-gnu
```

Полученный файл — самый обычный, настоящий исполняемый файл под
указанную архитектуру (можно проверить командой `file имя_программы`).
Для запуска на машине с другой архитектурой нужен либо компьютер с
реальным таким процессором, либо эмуляция (например, `qemu-aarch64`
для ARM64 на Linux).

⚠️ **Честное ограничение**: для итоговой линковки нужен установленный
кросс-компилятор под целевую платформу (например,
`gcc-aarch64-linux-gnu` для ARM64 на Debian/Ubuntu) — сам компилятор
Сферы это не устанавливает автоматически.

### Компиляция под Android

Требует дополнительно флаг `--android-sysroot ПУТЬ` — путь к папке
`sysroot` из настоящего Android NDK
(`toolchains/llvm/prebuilt/linux-x86_64/sysroot/`), плюс номер
API-уровня прямо в тройке платформы:

```bash
запустить программа.код -c --целевая-платформа aarch64-linux-android21 \
    --android-sysroot /путь/к/ndk/toolchains/llvm/prebuilt/linux-x86_64/sysroot
```

✅ Проверено полностью, включая реальный запуск на физическом
Android-устройстве через Termux (не только структура файла) —
программа со структурой, методом и циклом отработала корректно.

## Работа с сетью (TCP-сокеты)

Прямой доступ к системным сетевым функциям (POSIX) через тот же FFI-механизм,
что используется для графики (`подключить сеть;`, аналогично `графика.код`).
Нет отдельного, встроенного HTTP-клиента — вместо этого даны сами
"кирпичики" (сокеты), из которых HTTP собирается на самой Сфере, тем же
способом, каким `Список`/`Словарь` — просто библиотечный код, а не магия
компилятора.

```
подключить сеть;

функция главная() -> целое {
    целое32 сокет = создать_сокет(целое32(2), целое32(1), целое32(0));

    текст адрес_сервера = построить_адрес_сервера("93.184.216.34", целое32(80));
    подключиться(сокет, адрес_сервера, целое32(16));

    текст запрос = "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n";
    отправить_данные(сокет, запрос, длина(запрос), целое32(0));

    текст буфер = выделить_память(4096);
    целое получено = получить_данные(сокет, буфер, 4090, целое32(0));
    записать_целое32(буфер, получено, целое32(0));   // нуль-терминатор
    вывести(прочитать_текст_по_смещению(буфер, 0));

    закрыть_сокет(сокет);
    вернуть 0;
}
```

⚠️ **Важно про `получить_данные` (`recv`)** — TCP не гарантирует, что все
отправленные сервером данные придут за один вызов. Для полного ответа
нужно читать **в цикле**, пока `получить_данные` не вернёт `0`
(соединение закрыто — гарантированно произойдёт, если запрос содержал
`Connection: close`):

```
текст полный_ответ = "";
верно продолжать = да;
пока (продолжать) {
    текст буфер = выделить_память(4096);
    целое получено = получить_данные(сокет, буфер, 4090, целое32(0));
    если (получено > 0) {
        записать_целое32(буфер, получено, целое32(0));
        полный_ответ = полный_ответ + прочитать_текст_по_смещению(буфер, 0);
    } иначе {
        продолжать = нет;
    }
}
```

⚠️ **`построить_адрес_сервера` принимает только числовой IP-адрес**, не
доменное имя ("93.184.216.34", не "example.com") — настоящий DNS-резолвинг
(превращение домена в IP) пока не реализован, это честно названный
следующий шаг.

## Стандартная библиотека

### Текст

| Функция | Описание |
|---|---|
| `длина(текст)` | Длина строки в байтах |
| `подстрока(текст, начало, длина)` | Часть строки → `результат<текст>` |
| `содержит(текст, подстрока)` | Проверка вхождения → `верно` |
| `найти(текст, подстрока)` | Позиция вхождения → `результат<целое>` |
| `регистр_в_верхний(текст)` | В верхний регистр |
| `регистр_в_нижний(текст)` | В нижний регистр |
| `текст_в_целое(текст)` | Разбор числа → `результат<целое>` |

### Преобразование в текст

| Функция | Описание |
|---|---|
| `целое_в_текст(целое)` | Число → текст |
| `дробное_в_текст(дробное)` | Дробное → текст |
| `верно_в_текст(верно)` | `да`/`нет` → текст |

### Математика

| Функция | Описание |
|---|---|
| `абс(число)` | Модуль числа |
| `мин(а, б)` | Меньшее из двух |
| `макс(а, б)` | Большее из двух |

### Ввод-вывод

| Функция | Описание |
|---|---|
| `вывести(текст)` | Печать строки на экран |
| `прочитать_строку()` | Чтение строки из консоли → `результат<текст>` |
| `прочитать_файл(путь)` | Чтение файла целиком → `результат<текст>` |
| `записать_файл(путь, содержимое)` | Запись файла |
| `выполнить_команду(команда)` | Запуск команды операционной системы |
| `аргументы_командной_строки()` | Аргументы запуска программы → `Список<текст>` |

### Память "по смещению" (для низкоуровневой работы)

| Функция | Описание |
|---|---|
| `прочитать_целое32(буфер, смещение)` | Чтение 4 байт из буфера |

| `прочитать_текст_по_смещению(буфер, смещение)` | Чтение строки по адресу |
| `байт_текста(текст, индекс)` | Чтение одного байта текста (0-255) |

## Графика и UI (стандартная_библиотека/графика.код)

Отдельная, необязательная библиотека поверх SDL2 — требует установленных
`SDL2`/`SDL2_ttf` и флагов `--линковать SDL2 --линковать SDL2_ttf --линковать m`
при компиляции. Подключается через `подключить графика;`.

### Окно, холст, события

```
инициализировать(беззнак32(32));
инициализировать_шрифты();
текст окно = создать_окно("Заголовок", целое32(0), целое32(0), целое32(400), целое32(700), беззнак32(0));
текст рендерер = создать_холст(окно, целое32(-1), беззнак32(2));
```

### Кнопка

Цветной прямоугольник со скруглёнными углами и необязательной, автоматически
центрированной текстовой подписью (пустая строка `""` — кнопка без текста).

```
Кнопка моя_кнопка = Кнопка(целое32(20), целое32(15), целое32(160), целое32(50),
    беззнак8(70), беззнак8(130), беззнак8(230), "Нажми меня");
моя_кнопка.нарисовать(рендерер, шрифт);
если (моя_кнопка.содержит_точку(х_клика, у_клика)) { ... }
```

### Панель (навбар)

Фон на всю ширину плюс список кнопок внутри — то, что нужно для верхнего
или нижнего навбара. Каждая кнопка несёт свои собственные координаты —
панель их не вычисляет автоматически, только рисует фон и все кнопки
по очереди.

```
Список<Кнопка> кнопки = Список<Кнопка>();
кнопки.добавить(кнопка1);
кнопки.добавить(кнопка2);
Панель навбар = Панель(целое32(0), целое32(0), целое32(400), целое32(80),
    беззнак8(40), беззнак8(45), беззнак8(60), кнопки);
навбар.нарисовать(рендерер, шрифт);
целое32 индекс = навбар.кнопка_под_точкой(х_клика, у_клика); // -1, если мимо
```

### Картинки

Только формат `.bmp` — встроен в сам SDL2, без дополнительных библиотек.
⚠️ Честное, узкое ограничение: PNG/JPG потребовали бы отдельной библиотеки
SDL2_image, которую пришлось бы собирать отдельно. Конвертировать нужные
картинки в `.bmp` можно любым графическим редактором.

```
текст поверхность = загрузить_картинку("иконка.bmp");
текст текстура = создать_текстуру(рендерер, поверхность);
нарисовать_картинку_текстурой(рендерер, текстура, целое32(20), целое32(160), целое32(64), целое32(64));
```

### Поле ввода — `ПолеВвода`

Фон со скруглёнными углами (тот же вид, что и у `Кнопка`), поверх
которого рисуется введённый текст и мигающий текстовый курсор. Само поле
не подписывается на события самостоятельно — программа сама решает,
когда вызывать `добавить_текст`/`удалить_символ`, реагируя на события
`ввод_текста`/`нажатие_клавиши` в своём собственном цикле:

```
ПолеВвода поле = ПолеВвода(целое32(20), целое32(20), целое32(300), целое32(40),
    беззнак8(255), беззнак8(255), беззнак8(255), "", да);

// внутри цикла обработки событий:
если (тип_события == целое32(771)) {  // ввод_текста
    текст кусок = прочитать_текст_по_смещению(буфер_события, целое32(12));
    поле.добавить_текст(кусок);
}
если (тип_события == целое32(768)) {  // нажатие_клавиши
    целое32 код = прочитать_целое32(буфер_события, целое32(20));
    если (код == целое32(8)) {  // backspace
        поле.удалить_символ();
    }
}

поле.нарисовать(рендерер, шрифт, кадр);  // "кадр" — счётчик кадров, для мигания курсора
```

`удалить_символ()` корректно удаляет ровно один символ, а не байт —
важно для кириллицы (2 байта на символ в UTF-8): встроенная функция
`байт_текста(текст, индекс)` и вспомогательная `удалить_последний_символ`
находят правильную границу символа перед обрезкой строки.

## Известные ограничения

Список ниже — то, что **пока не работает или работает не полностью**,
на момент написания этого документа:

- Текст под ARC не покрывает результат, переданный напрямую в вызов
  функции без промежуточной переменной (`вывести(целое_в_текст(42));`)
- `Список<Контракт>` работает, но с известной утечкой памяти — см.
  подробности в разделе про контракты выше
- Контракт как тип возврата функции работает, но с той же самой,
  известной утечкой памяти (тот же корень — ARC не "видит насквозь"
  структуру, упакованную в контракт)
- Каналы поддерживают только целочисленные/указательные типы, только
  одностороннюю разовую передачу, без закрытия
- Нет `join` для потоков — только через канал можно дождаться значения
- Установщик среды разработки пока есть только для macOS

Полную, честную историю каждой находки, включая настоящие баги
(use-after-free, double-free) и то, как они были найдены и исправлены
— смотри в `ИСТОРИЯ_РАЗРАБОТКИ.md`.
