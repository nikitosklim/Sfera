# Панель разработчика

Графическая среда разработки для языка Сфера (вкладки "Обзор",
"Пакеты", "Документация") — написана на самом языке Сфера, поверх SDL2.

`графика.код` здесь — копия файла из `../стандартная_библиотека/`
(нужна рядом, поскольку `подключить` пока ищет файлы только по
относительному пути, без поддержки путей вида `../папка/файл`).

## Сборка (macOS)

```bash
sfera панель.код --только-собрать --линковать SDL2 --линковать SDL2_ttf --линковать m
```

## Самоустановка языка — теперь с выбором папки

Кнопка "Установить Сферу" открывает системный диалог выбора папки (через
`osascript`, встроенный `choose folder`) — устанавливает внутрь выбранной
папки подпапку `.sfera` с бинарниками. Прежнее, жёстко зашитое значение
(`~/.sfera`) осталось как значение по умолчанию, если диалог недоступен.

⚠️ Не проверено вживую (нет доступа к настоящему macOS здесь) — первая
реальная проверка, как и с Windows-установщиком, по факту присланной
ошибки, если она возникнет.

## Проверка обновлений — через GitHub Releases, не фейковый сервер

Раньше здесь была заглушка (`file:///tmp/фейковый_сервер_обновлений/...`)
— теперь панель делает настоящий запрос к
`https://api.github.com/repos/nikitosklim/Sfera/releases/latest` (через
`curl`, поскольку в языке пока нет HTTPS/TLS) и показывает найденную
версию и полный текст описания изменений прямо на вкладке "Обзор".

⚠️ **Важно**: для того чтобы проверка обновлений нашла что-то новое,
на GitHub должен существовать хотя бы один настоящий Release (с тегом
версии и текстом описания изменений) — панель их не создаёт сама, только
читает уже опубликованные. Кнопка "Установить обновление" открывает
страницу релиза в браузере (не подменяет `.app`-бандл автоматически —
рискованно менять файлы приложения, из которого оно само сейчас
запущено).

### Один релиз — сразу под несколько ОС

Релиз на GitHub может содержать сборки сразу под macOS/Windows/Linux/
Android — один и тот же номер версии не обязательно значит, что ИМЕННО
этой панели есть что скачивать (например, версия вышла с исправлением
только под Android). Панель не просто сравнивает номер версии — ищет
среди файлов релиза (assets) хотя бы один с меткой своей платформы в
имени (`метка_текущей_платформы()` — сейчас всегда `"macOS"`, поскольку
других панелей ещё не существует). Если такого файла нет — честно
сообщает "вышла версия X, но пока не собрана для macOS", не предлагает
"обновиться" на то, чего фактически нет для скачивания.

**Соглашение об именовании файлов релиза**, которого стоит держаться при
публикации на GitHub — имя файла должно содержать метку платформы:
`Панель-Сферы-macOS.zip`, `Sfera-Panel-Windows.zip`, `sfera-linux.tar.gz`,
`sfera-android.apk` и так далее. Метка ищется С УЧЁТОМ РЕГИСТРА: для Windows
ровно `Windows`. Архив для Windows собирает `../../собрать-релиз-windows.ps1`.

Версия панели и компилятора теперь единая — синхронизирована с
`Cargo.toml` в корне репозитория.

## Установка компилятора на Windows

`../установить-windows.ps1` в корне репозитория — установщик (Rust + LLVM
18 + Clang + сборка компилятора), уже проверенный на настоящей
Windows-машине вживую (несколько раундов исправлений по присланным
ошибкам — отсутствующий Clang, pthread при линковке и так далее).

## Панель разработчика на Windows — `панель_windows.код`

Отдельный файл (не `панель.код` — в языке пока нет условной компиляции
под разные ОС, поэтому платформенные различия — это два файла, как и с
установщиком). Экран и логика те же, отличаются только места, завязанные
на конкретную ОС: шрифт, домашняя папка, диалог выбора папки (PowerShell
вместо `osascript`), команды установки/удаления (`cmd.exe`-синтаксис
вместо `mkdir -p`/`cp`/`chmod`/`rm -rf`).

Сборка (после установки компилятора и Clang — см. выше):

```powershell
запустить панель_windows.код --только-собрать --линковать SDL2 --линковать SDL2_ttf --линковать m
```

`../установить-windows.ps1` теперь ставит и SDL2, и SDL2_ttf сам (по
точно такой же схеме, что LLVM и Clang — скачивает нужный релиз с
GitHub, распаковывает, прописывает пути) и передаёт компилятору, где их
искать, через переменную окружения `SFERA_LIB_PATHS` (компилятор
добавляет `-L<путь>` на линковку для каждого пути оттуда — см. main.rs,
`собрать_команду`). `.dll`-файлы копируются в ту же папку `bin`, что и
сам компилятор — она уже в PATH, так что собранная программа находит их
сама, без ручного копирования рядом с каждым `.exe`.

⚠️ Честно, что ещё не сделано:

**Сама панель (SDL2-графика) под Windows ещё не запускалась вживую** —
исходник компилируется и линкуется на Linux-песочнице (с Linux-версией
SDL2 — для проверки, что код синтаксически и семантически верен), но
первая настоящая проверка на Windows с реальным окном — ещё впереди.
